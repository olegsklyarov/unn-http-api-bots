# Лекция 11. JSON vs SQLite

Сравниваем два способа хранить счётчик: файл JSON и база SQLite.

Только стандартная библиотека Python. Внешних пакетов нет.

Запуск из этой папки:

```bash
make        # все эксперименты
make race   # гонка без lock
make lock   # JSON с file lock
make rps    # скорость обновления
```

## Что сравниваем

1. **Безопасность при гонке** — два процесса одновременно делают `n = n + 1`. Не потеряются ли обновления?
2. **Скорость обновления (RPS)** — сколько инкрементов в секунду делает один процесс.

## Эксперимент 1. Гонка (`make race`)

Два процесса, каждый делает `N = 500` инкрементов. Ожидается `1000`.

### JSON без блокировки — [`inc_json.py`](inc_json.py)

Читает файл → прибавляет 1 → пишет обратно. Блокировки нет.

Типичная гонка (*lost update*):

1. процесс A читает `n = 0`
2. процесс B читает `n = 0`
3. A пишет `1`
4. B пишет `1`

Ожидалось `2`, осталось `1`. Один инкремент пропал.

`os.replace` здесь только не даёт читать битый JSON: новый файл подменяется целиком. Потерянное обновление это **не** лечит — оба процесса уже решили писать по старому `n`.

Итог обычно около `500…550` вместо `1000`. Если процессы идут почти синхронно, часто получается ровно `500`: каждая пара попыток даёт только `+1`.

### SQLite — [`inc_sqlite.py`](inc_sqlite.py)

Каждый инкремент — `UPDATE … SET n = n + 1` и `commit`. Второй процесс при занятой базе **ждёт** (`timeout=30`), а не затирает значение.

Итог: ровно `1000`.

## Эксперимент 2. File lock (`make lock`)

Тот же JSON, но на всё чтение и запись берётся `fcntl.LOCK_EX` — [`inc_json_lock.py`](inc_json_lock.py).

Пока один процесс держит lock, второй ждёт. Read-modify-write становится атомарным для процессов на одной машине.

Итог: ровно `1000`. Значит, гонка была из‑за отсутствия синхронизации, а не из‑за «плохого JSON как формата».

## Эксперимент 3. RPS (`make rps`)

Один процесс, `BENCH = 5000` инкрементов подряд. Цикл внутри `inc_*.py`, чтобы мерить запись, а не запуск Python.

Сравниваем безопасные обновления: JSON с lock и SQLite (`journal_mode=WAL`, `synchronous=NORMAL`).

Ожидаемо SQLite заметно быстрее: меняет одну строку. JSON каждый раз блокирует файл и переписывает весь документ.
